# Строки для резюме

Каждое число взято из файлов в `results/` (источник указан в скобках).

- Собрал открытый бенчмарк поиска по законам РФ в формате MTEB: 3786 статей шести кодексов, 18.5 тыс. синтетических вопросов от двух LLM разных семейств, три среза обобщения, подмножество с повторной разметкой и отдельный трудный набор. Показал, что автоматическая разметка «вопрос → одна статья» неполна для 21% вопросов (`corpus_stats.json`, `dataset_stats*.json`, `golden_stats.json`).
- Дообучил multilingual-e5-small (118M) за 19 минут на одной RTX 3070: разметка обучающих пар моделью-учителем FRIDA (823M) плюс дистилляция её ранжирования (DistillKL), GradCache, свой батч-сэмплер без ложных негативов по статьям. nDCG@10 на тесте вырос с 0.802 до 0.859 (+0.057, 95% ДИ [+0.042; +0.073]) — это полностью закрыло разрыв до multilingual-e5-large (560M, 0.859; разница незначима) при задержке на CPU в 6.8 раза меньше (`bootstrap.csv`, `headline.json`, `speed.json`).
- Сравнил 12 эмбеддеров и BM25 с парным бутстрапом по срезам, типам вопросов и кодексам; показал, что даёт дообучение (бытовые вопросы 0.569 → 0.701) и где оно перестаёт работать (новые кодексы: +0.026, ДИ включает ноль; общий домен RuBQ 0.686 → 0.659) (`bootstrap.csv`, `forgetting.json`, `figures/qtypes.csv`).
- Внедрил модель в свой RAG-сервис по Трудовому кодексу с переключением через конфиг и отдельным индексом на модель: на собранном для этого трудном наборе из 716 вопросов MRR@5 вырос с 0.688 до 0.793 (+0.105, ДИ [+0.084; +0.127]). Замер «было/стало» делался до переключения — на более раннем чекпоинте он поймал регрессию, которой не было видно на насыщенном родном наборе сервиса.
- Весь выбор гиперпараметров и рецепта — только по dev, журналом в файле (`recipe_selection.json`); каждое число README воспроизводится одним скриптом (`scripts/run_eval.sh`), 88 быстрых тестов и линтер, которые гоняет GitHub Actions.
